## 一、生产化（让项目可演示上线）

### 1.1 Docker 全项目容器化 ✅ 已完成
**当前**：docker compose up -d 一键启动全部三个服务（redis + 后端 + 前端）
**详情**：三步 Dockerfile 多阶段构建 + nginx 反向代理 + SSE 流式支持

### 1.2 云部署
**当前**：只能在本地 localhost 演示
**目标**：拿到公网 URL，面试时直接打开浏览器
**方案**：阿里云 ECS / 腾讯云轻量（学生价 ～100 元/年）→ 安装 Docker → 部署项目 → Nginx 反向代理

**目标**：https 访问，更专业的演示效果

**详情**：BaseService 支持注入外部 LLMService 实例，main.py 启动时注入 agent.llm 到所有 Tool

## 二、AI Agent 核心（技术深度加分项）

### 2.1 MCP 协议接入
**当前**：手写 Tool 体系（BaseTool + ToolRegistry），不支持标准协议
**目标**：让 JobPilot 可以通过 MCP 标准协议调用外部工具
**可以做什么**：
- 接入天气 MCP 服务 → Agent 可以回答「北京这周适合面试吗」
- 接入邮件 MCP 服务 → Agent 可以代发求职邮件
- 接入日历 MCP 服务 → Agent 可以帮安排面试时间
- 接入 GitHub MCP 服务 → Agent 可以查看面试官的 GitHub 项目
**面试价值**：MCP 是 2025 年新兴标准，从 Tool Use 到 MCP 的演进能体现技术敏感度

### 2.2 多 Agent 协作架构
**当前**：单 Agent 架构（一个 Planner 决策所有事情）
**目标**：拆分为多个专业 Agent 协作
- **简历 Agent**：专门处理简历解析和分析
- **JD Agent**：专门处理岗位分析
- **检索 Agent**：专门负责 RAG 检索
- **决策 Agent**：负责汇总和最终判断
**面试价值**：体现架构设计能力，和 crewAI / 多 Agent 系统对齐

### 2.3 Reflexion 自我反思机制
**当前**：Agent 失败时只返回「已达到最大步数」
**目标**：Agent 失败后自我反思「为什么会失败」「下次怎么改进」，然后重试
**面试价值**：高级 Agent 架构能力，是大厂看重的能力

### 2.4 Human-in-the-Loop
**当前**：Agent 全自动执行，用户可以打断
**目标**：关键节点（如发送邮件前）让用户确认
**涉及**：LangGraph 的 `interrupt_before` + 前端确认弹窗
**面试价值**：体现「AI 不是全自动的，关键决策需要人确认」的安全意识
